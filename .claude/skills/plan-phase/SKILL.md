# Поведение скилла

Скилл принимает аргумент — готовый PRD документ. Необходимо прочитать файл PRD, разработать план и сохранить его в папку docs; если папки нет, она создаётся автоматически. Имя файла формируется автоматически: название переводится на английский язык и приводится к формату kebab-case (например, file-upload-PLAN.md).

# Структура скилла планирования

Скилл создаётся по аналогии с PRD-скиллом: в папке skills создаётся папка plan с файлом skill.md.

# Описание скилла:

**Название**: plan
**Задача**: разбить PRD на фазы реализации
**Когда использовать**: когда PRD готов и нужно составить план разработки с независимыми фазами
**Действие**: прочитать PRD из файла, создать план реализации, сохранить в файл

# Структура документа-плана

Документ плана включает:

**Заголовок**: название фичи
**PRD**: ссылка или название исходного PRD
**Дата**: текущая дата

## Блоки фаз — для каждой фазы:

Номер и название фазы (подзаголовок)

**Цель** — что даёт эта фаза
**Затрагивает** — backend / frontend / database и т. д.
**Задачи** — список конкретных задач (не более пяти)

- [] Задача 1
- [] Задача 2

  и т.д.

**Критерий готовности** — конкретное условие, при котором фаза считается завершённой

# Правила разбивки на фазы

- Каждая фаза должна давать рабочий результат, который можно проверить.
- Каждая фаза должна быть независимой и завершённой. Можно остановитьься на любой фазе и получить рабочий результат.
- Первая фаза должна быть минимальной, чтобы можно было быстро получить рабочий результат. (Tracer bullet)
- Каждая фаза должна быть проверяема по критериям готовности.
- Не более пяти задач на фазу. Если задач больше — разбить на несколько фаз.
- Backend и frontend должны быть разбиты на отдельные фазы.
- Frontend выполняется только после того, как backend готов и проверен.

# Правила для скилла при чтении PRD

- Читать PRD внимательно.
- План должен покрывать все критерии готовности из PRD.
- Нельзя добавлять задачи, которых нет в PRD.
- Если PRD неполный — задать уточняющие вопросы до создания плана.
